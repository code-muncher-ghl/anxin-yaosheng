摘要

「安心药声」要解决的问题很具体：一位 70 岁的老人拿到一盒药，说明书上的字号小于 5 号字，术语密集，而他同时还在吃另外四种药。他不知道这五种药会不会「打架」，也不好意思每次都打电话问子女。

本报告记录这个产品的 AI 技术实现全过程：如何用多模态大模型把一张说明书照片变成 11 个结构化字段；如何用检索增强生成（RAG）保证每句话都能点回原文；如何用 Function Calling 让模型自己决定「该查什么」；以及最重要的——如何用四道护栏，把医疗场景里最危险的「一本正经地胡说八道」压到最低。

核心结论：20 条评测用例上，安全率 100%、行为符合率 100%、关键信息准确率 100%，数字幻觉率 0%；单次解读端到端约 8 秒，模型成本低于 0.01 元。

一项目背景与技术目标

1.1 问题定义

从技术视角看，这个场景有三层难点，层层递进：

  • 感知层：说明书是纸质、多栏、字号极小、常有反光和折痕的文档，OCR 与版面理解都容易出错。
  • 理解层：说明书是写给专业人士的，一个「慎用」和「禁用」的差别，直接关系到要不要吃。
  • 决策层：老人真正的问题往往不在说明书里（「能不能和降压药一起吃」），需要跨文档、跨知识库推理。

    • 这三层分别对应三个技术模块：多模态结构化解析、受约束的口语化生成、Agent + 知识库的跨文档检索。

    二总体技术方案

    2.1 四层架构

    系统按「输入层—理解层—推理层—安全输出层」四层解耦。直接好处是：换一个大模型供应商，或者换一个病种（比如从降压药换到降糖药），只需要替换其中一层，其余代码不动。

    2.2 端到端流程

    一次完整交互包含两条链路：解读链路（拍照 → 结构化 → 播报稿 → TTS）与问答链路（提问 → Agent 决定工具 → 证据召回 → 受约束生成 → 护栏复核）。两条链路共用同一套证据编号体系，所以用户在播报里听到的每一句，和问答里看到的每一个 [n]，指向的是同一份原文。

    2.3 关键设计取舍

    四Prompt 工程设计

    4.1 设计方法论

    本项目共有 6 个生产级 Prompt（解析、播报稿、RAG 问答、答案复核、多药冲突、家属摘要），全部采用「角色 + 任务 + 硬约束 + 输出结构 + 反例/示例」五段式。三个原则贯穿始终：

  • 可溯源优先：所有抽取类任务强制要求 evidence 字段，模型必须指认「这句话是从哪来的」。
  • 禁止补全：原文没有的字段返回 null，而不是让模型用医学常识填空——这是幻觉的最大来源。
  • 拒答写进 Prompt：把「什么时候必须说不知道」写成规则，而不是靠事后关键词过滤。

    • 4.2 说明书解析 Prompt

    解析 Prompt 的核心是一条反直觉的要求：要求模型不要发挥。传统做法是让模型「提取说明书要点」，模型会顺手补上常识（说明书没写饭前饭后，它会写「建议饭后服用」）。我们改为：字段无原文支撑时必须为 null，并附 evidence 原文片段。这样即使模型想编，也没有地方放。

    【硬约束】
1. 只抽取原文真实存在的信息。禁止用你的医药知识补全、推断、缩写。原文没有的字段一律输出 null。
2. 数字、单位、频次必须逐字照抄。例如原文「一次1片（20mg），一日1次」不得改写成「每天20mg」。
3. 每个字段都要给 evidence，填入支撑它的原文片段（完整句子，≤120字）。找不到支撑原文的字段 value 设为 null。
4. 图中无法辨认的字用「□」占位，禁止猜测补全。

    4.3 播报稿生成 Prompt

    播报稿要求 260~340 字、每句不超过 20 字、四个固定段落（治什么 / 怎么吃 / 当心什么 / 何时就医）。数字必须与结构化字段逐字一致；生成完成后，代码再做一次数字比对，出现字段里没有的数字就标记告警。这是「生成后校验」而非「仅靠 Prompt 约束」的典型例子。

    4.4 RAG 问答 Prompt 与 few-shot

    第一版问答 Prompt 只有规则没有示例，模型在小样本下表现不稳定：证据里明明写了「一日1次」，它却回答「说明书没写」。加入 3 个 few-shot 示例（足够→直接答、换问法→照样答、真没有→说不知道）后，回答稳定性明显提升。这说明对中小参数模型而言，示例比规则更有效。

    【示例一：证据足够，直接答】
证据：[1] 【用法用量】口服。成人常用量：一次1片（20mg），一日1次。
问题：一天吃几次？
回答：一天吃1次，一次吃1片。[1]

【示例三：证据里没有，必须说不知道】
证据：[1] 【禁忌】对本品任何成分过敏者禁用。
问题：糖尿病人能吃吗？
回答：说明书里没写糖尿病的情况，建议问一下药师。[1]

    4.5 复核 Prompt（Verifier）

    复核员是独立的第二次调用，逐句核对数字、断言、引用与风险建议。实践中发现一个陷阱：弱模型容易「过度否决」——只输出 pass=false 却不给具体问题，导致正确答案被换成保守废话。因此我们在代码层加了一条：只有明确列出 unsupported_numbers / unsupported_claims / invalid_citations 时，否决才生效；否则视为通过。

    五RAG 实现

    5.1 切块策略

    说明书天然带章节标记（【用法用量】【禁忌】…），我们直接按章节切块，一句一条，形成「最小证据单元」。这样引用可以精确到句子，而不是「第 2 页」这种粗粒度。单张说明书通常切出 12~20 个 chunk。

    5.2 检索算法

    采用 BM25（k1=1.5, b=0.75）+ 章节意图先验的混合打分：

    score = BM25(query, chunk) + 2.0 × prior(section)
# prior 由意图词触发：出现「怎么吃/几次/饭前」→ dosage +0.22
# 最终得分低于最高分 35% 的 chunk 被丢弃
    代码 5-1　混合打分公式

    为什么不用向量库？单文档语料只有 1~3k 字，向量检索的优势体现不出来，反而引入 embedding 服务依赖，答辩现场断网就不可用。接口层已按 Retriever 抽象，后续接 bge-m3 只需替换 retrieve() 一个方法。

    5.3 同义词扩展

    老人不会说「用法用量」，他们说「一天吃几次」。说明书原文写的是「一日1次」，BM25 无法命中。我们加了一层口语→书面语的同义归一（一天→一日、吃→服用、副作用→不良反应、放→贮藏 等 18 组），检索命中率显著提升。

    这个药要放冰箱吗（未命中）【贮藏】遮光，密封，在干燥处保存

    6.3 引用编号对齐

    工程上一个很容易踩的坑：工具返回的证据里自带 chunk id（如 cid=14），模型会直接引用 [14]，而前端只认 [1]~[n]。解决办法是在系统提示里明确「引用编号 = 第几次工具调用」，并在护栏里校验编号是否越界。

    七语音合成链路

    7.1 选型

    选用微软 Edge 神经语音（edge-tts），原因是免费、无需 Key、中文音色自然、支持语速与音量参数，并且可以离线缓存。默认音色 zh-CN-XiaoxiaoNeural，语速 −12%，适配老年听力。

    7.2 数字与单位归一化

    TTS 直接读「20mg」会念成「二十 M G」。我们在合成前做一层文本归一：阿拉伯数字转中文数字、英文单位转中文（mg→毫克、ml→毫升）、百分号转「百分之」。这一层看似简单，却是「听得懂」与「听不懂」的分界线。

    原文直接朗读归一化后
    一次1片（20mg），一日1次一次一 M G，一日一次一次一片，二十毫克，一日一次
    0.25g零点二五 G零点二五克
    血压下降 30%下降三十 percent下降百分之三十

    7.3 分段合成与缓存

    长文本按句子切分为 ≤220 字的片段，逐段合成后用 ffmpeg 拼接（imageio-ffmpeg 自带二进制，免安装）。合成结果按内容 hash 缓存，重复播报不再请求。

    八幻觉治理：四道闸门

    8.1 幻觉从哪里来

    在这个场景里，幻觉有五种典型形态，危害依次递增：

    类型例子危害对应闸门
    数字幻觉说明书是 1 片，答成 2 片极高，可能过量① 数字接地
    程度幻觉原文「慎用」，答成「禁用」高，可能延误用药④ 独立复核
    引用幻觉编一个不存在的 [5]中，破坏可信度② 引用校验
    越界行医「你可以停药了」极高，医疗风险③ 危险建议拦截
    无据发挥说明书没写，凭常识作答中Prompt 拒答规则 + ③

    8.2 四道闸门

  • 闸门 ①　数字接地：用正则抽取回答中的「数字+单位」，逐个在证据原文中查找；任何找不到的数字，整段降级。
  • 闸门 ②　引用校验：抽取 [n]，检查是否落在召回编号范围内。
  • 闸门 ③　危险建议拦截：命中「停药/换药/加量/诊断/治愈」类模式 → 强制改写为「请医生判断」。
  • 闸门 ④　独立复核：另起一次模型调用，逐句核对；只有明确列出问题才否决。

    9.4 失败案例分析

    剩余误差主要来自两类：一是关键词判定过严（例如答「饭前饭后都可以」而用例要求「不影响」），属于评测口径问题而非模型错误；二是小参数模型在长证据下的指令遵循波动，同一问题两次调用可能出现一次拒答。后者通过降低 temperature（0.1~0.2）与增加 few-shot 缓解，但不能完全消除——这正是我们坚持「生成后复核」而不只依赖单次生成的原因。

    十一局限与改进

  • 示例说明书为教学用文本，真实场景需覆盖更多版面（多栏、折痕、反光），并接入药品追溯码做二次校验。
